WuK Project – ArduCopter Development Work List

Scope
- Implement dual UART comms loop (FC <-> Arduino) that follows main loop cadence without burdening scheduler.
- Add ModeMorph (transition) and ModeGround (differential thrust ground/water) plus channel-driven overrides (RC7/8/9).
- Add morph-aware mixer adjustments (0–45° compensation, then motor idle/cut, then hand-off to Arduino to finish to 90°) and safe sequencing.

Assumptions / Constraints
- Target branch: current ardupilot tree (4.x style). No external libs.
- UART uses AP_SerialManager; non-blocking writes; fixed framing; small payloads.
- RC channel mapping: RC9 triggers transition; RC7/RC8 are pass-through commands to Arduino (no FC control loop effects).
- Safety: retain arming/failsafe/crash-check unless explicitly gated in custom modes; do not break spool-state handling.

Task Breakdown (ordered)

1) Serial link design & plumbing
- Define protocol framing (example): [0xAA][MsgId][Len][Payload...][CRC8]. Keep payload <=16 bytes.
- Message set (from FC to Arduino):
  * CMD_ARM_SERVO: port=ARM, value=angle_deg (0–90)
  * CMD_ACT1: port=ACT1 (RC7 mapped), value=0–2000
  * CMD_ACT2: port=ACT2 (RC8 mapped), value=0–2000
  * CMD_STATUS_REQ: periodic ping to confirm link
- Message set (from Arduino to FC):
  * RSP_ACK (echo MsgId)
  * RSP_STATUS: current angles/states, error flags
- Serialization: little-endian; throttle frequency 50 Hz max; coalesce unchanged messages (only send on change for RC7/8 except heartbeat).
- Code hooks:
  * Add SERIALx_PROTOCOL slot via AP_SerialManager (USER/ custom id). Obtain UARTDriver in `Copter::init_ardupilot()` or similar init path (see `Copter.cpp`, search for serialmanager usage).
  * Add a 50 Hz SCHED_TASK entry in `Copter::scheduler_tasks` (top of `Copter.cpp`) invoking a new method `Copter::uart_wuk_update()`; implement in `Copter.cpp` near other scheduler handlers. Ensure non-blocking writes with `uart->txspace()` checks.
  * Maintain a small ring buffer/queue in a new module `libraries/AP_WuKComms/` (create) or inside `Copter` if scoping locally; expose `enqueue_cmd` / `service_io` APIs. Drop frames if queue full to protect scheduler.
  * Add params in a new table (e.g., `wuk_params.h/cpp` under ArduCopter or reuse existing `Parameters.cpp`) for baud/port; wire into serialmanager selection.

2) RC channel mapping and override logic
- RC9 (>1800) triggers ModeMorph; RC9 <1200 forces Loiter (baseline); mid-band no effect.
- RC7/RC8: read each loop; if changed by > deadband, enqueue CMD_ACT1/CMD_ACT2 with mapped value; no mode changes.
- Hook point: `Copter::rc_loop()` after `read_radio()` and before `rc().read_mode_switch()`; ensure failsafes can still override.
- Record ModeReason for logging when forcing mode changes.
 - Implementation steps:
   * In `Copter.cpp` `rc_loop()`, insert a call to `process_wuk_switches()` that reads RC7/8/9 raw values.
   * Implement `process_wuk_switches()` in `Copter.cpp` (or new `wuk_switches.cpp` compiled via `wscript`) to:
     - Detect RC9 rising >1800: call `set_mode(Mode::Number::MORPH, ModeReason::RC_COMMAND)`.
     - Detect RC9 falling <1200: call `set_mode(Mode::Number::LOITER, ModeReason::RC_COMMAND)` and send hold-90° command.
     - For RC7/8 deltas beyond deadband: call `wuk_comms.enqueue_cmd(CMD_ACT1/2, value)`.
   * Ensure failsafe order: keep `rc().read_mode_switch()` after this block so standard mode switch still runs; allow failsafes to override.

4) ModeMorph behavior [DONE]
- Entry condition: RC9 > 1800.
- Generate morph_angle trajectory: 0→45° over configurable duration (default 3s). Per-cycle delta = dt * rate.
- While angle <45°:
  * Send CMD_ARM_SERVO with current angle.
  * Apply mixer compensation for first 0–45° (see Task 6) so roll/yaw control is maintained.
- At angle >=45°:
  * Command motors to idle/cut (respect spool state). Wait 2s dwell.
  * Send CMD_ARM_SERVO with value=90° to force completion.
  * Switch to ModeGround.
- Exit condition: dwell finished and hand-off done, or RC9 drops <1200 (immediate Loiter fallback; send latest servo state but skip dwell).
- Safety: keep land/crash detectors aware—mark land_complete when throttling to idle; avoid false crash triggers if possible.
 - Implementation steps:
   * In `mode_morph.cpp::run()`: compute dt from scheduler, integrate morph_angle up to 45° using param `MORPH_RATE`. [DONE]
   * Before 45°: call `wuk_comms.enqueue_cmd(CMD_ARM_SERVO, angle)`; call `motors->set_morph_angle(angle)` (new API, Task 6). Use existing attitude control for stabilization. [DONE - API call commented out]
   * On reaching 45°: set motors desired spool state to idle/cut (`AP_Motors::set_desired_spool_state(GROUND_IDLE)`), start dwell timer (`MORPH_DWELL`). [DONE]
   * After dwell: send `CMD_ARM_SERVO` with 90°, call `set_mode(Mode::Number::GROUND, ModeReason::MORPH_COMPLETE)`. [DONE]
   * On RC9 drop <1200: break to Loiter, send hold-90° once, skip dwell. [DONE]
   * Consider setting `set_land_complete(true)` when cutting throttle to avoid crash-check false positives. [TODO]
